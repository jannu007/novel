# 小説執筆スタジオ

完全無料・ブラウザだけで動く小説執筆アプリです。ビルド済みアプリはブラウザから
**そのままインストール**して使えます（APKもストア登録も不要）。サーバー不要、課金なしで、Amazon
KDP（Kindleダイレクト・パブリッシング）で販売できる原稿（EPUB / DOCX /
印刷用PDF）を作成できます。

## インストールして使う（PWA）

このアプリは[インストール可能なPWA](https://web.dev/progressive-web-apps/)です。
GitHub Pagesで公開したURLをブラウザで開くと、以下のようにインストールできます。

- **デスクトップ（Chrome / Edge）**：アドレスバーのインストールアイコン、または画面右上の
  「📲 インストール」ボタンをクリック。
- **Android（Chrome）**：メニュー（⋮）→「アプリをインストール」、または画面右上の
  「📲 インストール」ボタンをタップ。
- **iOS（Safari）**：共有ボタン →「ホーム画面に追加」。

インストール後は独立したウィンドウ（アイコン付き）で起動し、一度読み込んでおけば
オフラインでも執筆を続けられます（`public/sw.js` によるオフラインキャッシュ）。

## 主な機能

- **執筆**：作品ごとに章を分けて本文を執筆。自動保存、文字数カウント、目標達成率表示。スマートフォンなど
  画面が狭い環境では、本文欄を下から上にスワイプ（末尾までスクロールした状態からさらに上へ）すると
  全画面の執筆モードになり、上から下にスワイプ（先頭までスクロールした状態からさらに下へ）すると元に戻ります。
- **ルビ（振り仮名）・傍点**：執筆画面で文字を選んで「ルビ」「傍点」ボタンを押すと、本文に
  `｜漢字《かんじ》`・`《《強調》》` という記法（青空文庫・小説投稿サイトと同じ書き方）が入ります。
  漢字の直後に `《よみ》` と書けば親文字は自動判定されます。記号自体を書きたいときは `※《` のように
  `※` でエスケープできます。この記法は EPUB では `<ruby>`、DOCX では Word 標準のルビ（`w:ruby`／圏点）、
  印刷用PDFと縦書きリーダーではそれぞれの体裁に自動で組み替えられます。ルビの読みは本文の文字数には
  含めずに数えます。
- **推敲・校正（自動チェック）**：「推敲」画面で、出版原稿として整えておきたい点を端末内だけで
  自動チェックします（外部AIやサーバーは使いません）。
  - 検出できる項目：半角カタカナ、半角の！？、三点リーダー（`...`／奇数個の`…`）、ダッシュの統一、
    「！」「？」のあとの全角スペース、段落の字下げ、閉じ括弧の直前の句点、括弧の対応漏れ、
    句読点の重複、波ダッシュの統一、欧文引用符、段落末の句点漏れ、一文が長い、文末表現の連続、
    同語の繰り返し、重言、ら抜き言葉（地の文のみ）、助詞の重複、算用数字の漢数字化（任意）など。
  - 機械的に直せる指摘は**1件ずつ／まとめて自動修正**でき、直前の状態にいつでも**元に戻せます**
    （取り消し用のひかえは端末に保存されるため、画面を移動しても残ります）。
  - **表記ゆれ**（「できる／出来る」「サーバー／サーバ」など）を検出し、どちらに統一するかを
    ボタンひとつで一括置換できます。
  - **文体の傾向**を数値化した目安（会話文の比率・平均の文の長さ・漢字の比率・一文あたりの読点・
    文末表現のバリエーションなど）と、総合スコアを表示します。
  - チェック項目は個別にオン／オフでき、設定は端末に保存されます。
- **キャラクター管理**：登場人物のプロフィール・設定メモを一覧管理。
- **プロット管理**：あらすじと起承転結・シーン単位のプロットポイントを整理。
- **起承転結の自動下書き生成**：あらすじ・キャラクター設定・プロットポイントから、外部AIを一切使わず
  端末内だけで「起」「承」「転」「結」それぞれ約1,300字（4パート合計5,000字以上）の下書きを自動で組み立て、章として反映できます
  （テンプレート合成によるシンプルな下書きのため、そのままではなく必ず読み返して手直ししてください）。
- **章ごとの指示リライト**：執筆画面の「章をAIで修正」から、「情景描写を増やす」「心情描写を増やす」「会話を増やす」
  「緊迫感を高める」「もっと簡潔にする」という指示メニューを選ぶと、外部AIを使わず端末内のルールだけで本文を調整します
  （通信は発生しません）。必ずプレビューで内容を確認してから反映する仕組みで、反映後も1回だけ元に戻せます。
  起承転結のつなぎ文は「情感句＋述部」のように独立した部品を組み合わせる方式にしており、1パートあたり
  数千通りの組み合わせを生成できます。さらに一度使った組み合わせは端末内（IndexedDB）に記録して次回以降の
  作品では優先的に避けるため、同じ作品の中でも複数の作品をまたいでも言い回しが重複しにくくなっています
  （テンプレートの組み合わせという性質上、作品数が増えれば完全に重複をゼロにはできませんが、実用上ほとんど
  気にならない水準まで抑えています）。また、主人公キャラクターを登録していない場合でも、本文の主語が
  「主人公」という一般名詞のままにならないよう、作品ごとに決定的な人名を自動で割り当てます。
- **表紙・挿し絵の自動生成**：タイトル・ジャンルから、Canvas APIだけで水彩画風の表紙デザインと各章の
  装飾イラストを自動生成（実写や生成AIのイラストではなく、にじみと筆致による水彩表現）。EPUB・DOCX・
  印刷用PDFに自動挿入され、表紙はPNG単体でもダウンロードできます。
- **縦書きリーダー**：文庫本のように縦書き・ページめくりで読めるプレビュー画面。スワイプ（左→右で次のページ）
  でページがめくれます。
- **出版準備**：書誌情報（タイトル・著者名・ジャンル・判型）の入力とKDP提出前チェックリスト（校正の
  「要修正」項目が残っていないかも自動で確認します）。
- **書き出し**：
  - EPUB（Kindle本アップロード用。自動生成した表紙・章ごとの挿し絵・目次を含む）
  - DOCX（Word。電子書籍・ペーパーバック双方に対応。表紙・挿し絵・目次ページ入り）
  - 印刷用PDFプレビュー（ペーパーバック判型に合わせたレイアウトをブラウザの印刷機能でPDF保存。表紙・目次・挿し絵入り）
  - TXT（プレーンテキスト。ルビ記法を残したまま出力すれば小説投稿サイトにそのまま貼り付けられます。本文だけの出力も選べます）
  - バックアップJSON（作品データ全体のエクスポート／インポート）
- **KDP出版ガイド**：KDPアカウント作成からアップロード、審査までの手順を日本語で解説。

## データの保存について

すべてのデータはブラウザの IndexedDB にのみ保存されます（サーバーには一切送信されません）。
ブラウザのデータを消去すると原稿も失われるため、「出版準備」画面から定期的に
**バックアップ（JSON）** を保存してください。別端末やブラウザに移す場合は、ダッシュボードの
「バックアップを読み込む」から取り込めます。

## 開発

```bash
npm install
npm run dev      # 開発サーバーを起動
npm run build    # 本番ビルド（dist/ に出力）
npm run preview  # ビルド結果をローカルで確認
```

ビルド成果物は静的ファイルのみなので、GitHub Pages・Cloudflare Pages・Netlify
などの無料静的ホスティングにそのままデプロイできます（ルーティングは `HashRouter`
を、アセット参照は相対パス（`base: './'`）を使用しているため、リポジトリ名のサブパス
配下にデプロイしてもサーバー側のリライト設定は不要です）。

### GitHub Pagesへのデプロイ

`.github/workflows/deploy-pages.yml` が `main` ブランチへのプッシュのたびに自動ビルド・
自動デプロイします。初回のみ、リポジトリの **Settings → Pages → Build and
deployment → Source** を `GitHub Actions` に設定してください。公開後のURLは
`https://<ユーザー名>.github.io/<リポジトリ名>/` になります。

## 技術スタック

- React 19 + TypeScript + Vite（`base: './'` で相対パス配信、サブパス配置に対応）
- react-router-dom（HashRouter）
- idb-keyval（IndexedDBラッパー、ローカル永続化）
- jszip / docx / file-saver（EPUB・DOCX書き出し）
- Canvas API（`src/lib/coverGenerator.ts`）による表紙・挿し絵の自動デザイン生成
- Service Worker（`public/sw.js`）+ Web App Manifest によるインストール可能PWA

外部APIやサーバーには依存しておらず、完全にクライアントサイドのみで完結します。
起承転結の下書き生成（`src/lib/draftGenerator.ts`）、校正・推敲（`src/lib/proofreader.ts`）、
ルビ・傍点記法の解析（`src/lib/inlineMarkup.ts`）、表紙・挿し絵の自動生成も、
外部の生成AIサービスを一切呼び出さず、すべて端末内のロジックだけで完結しています。

### 校正エンジンの設計

指摘はすべて「本文中の位置（`index`）と長さ（`length`）」で表現し、自動修正できるものだけが
置換後の文字列（`replacement`）を持ちます。位置ベースに統一しているため、複数のルールの修正を
後ろの位置から順に適用するだけで、前方の位置をずらさずにまとめて反映できます。範囲が重なる指摘は
先に処理したほうを優先して読み飛ばします。

表記ゆれの集計と一括置換では、「サーバ」が「サーバー」の一部でもあるような部分文字列の関係を
扱う必要があります。数えるときは長い表記から順に伏せ字へ置き換えて二重に数えないようにし、
統一するときはいったんすべての候補を目印に置き換えてから統一先の表記に戻すことで、
「サーバーー」のような壊れ方を防いでいます。
